---
title: "Type mapping"
description: "How TypeScript types translate to Solidity types."
---

Scriipture maps TypeScript's type system onto Solidity's. Most conversions are 1:1; a few require Scriipture-provided types.

## Primitive types

| TypeScript | Solidity | Notes |
| --- | --- | --- |
| `bigint` | `uint256` | Default. Use branded types for other widths. |
| `Uint8`, `Uint16`, ... `Uint256` | `uint8` ... `uint256` | Explicit widths. |
| `Int8`, ..., `Int256` | `int8` ... `int256` | Signed integers. |
| `boolean` | `bool` |  |
| `string` | `string` | UTF-8. |
| `Bytes`, `Bytes32` | `bytes`, `bytes32` | Fixed and dynamic. |
| `Address` | `address` | Scriipture-provided branded type. |

## Collections

<CodeGroup>

```ts Collections.ts
@storage balances: Map<Address, bigint> = new Map();
@storage names: string[] = [];
@storage user: { name: string; age: bigint } = { name: "", age: 0n };
```

```solidity Collections.sol
mapping(address => uint256) public balances;
string[] public names;

struct User { string name; uint256 age; }
User public user;
```

</CodeGroup>

<Warning>
  `Map` in a Scriipture contract compiles to Solidity `mapping`. It does not support `.size` or iteration, matching Solidity semantics.
</Warning>

## Enums

TypeScript `enum` compiles to Solidity `enum`. Prefer numeric enums; string enums are rejected by the parser.

See [Decorators](/concepts/decorators) for how these types combine with visibility and access-control decorators.
